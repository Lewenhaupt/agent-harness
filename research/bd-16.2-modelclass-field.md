# Explicit modelClass field on AgentDefinition — Research Plan (bd-16.2)

Follow-up to bd-16. Today `MODEL_TO_CLASS` (src/model-classes.ts) is a string-keyed map from bare model ids to capability tiers; the agent→class relationship is implicit. This plan makes it explicit.

## Decision

Add an optional `modelClass?: ModelClass` to `AgentDefinition`, populate it on all `DEFAULT_AGENTS`, and use it as the primary class source in candidate resolution. `MODEL_TO_CLASS` stays as a fallback for bare-model strings (backward compat; unknown models stay class-of-one).

## Changes (ordered)

1. `src/model-classes.ts` — `candidatesForModel(model: string, modelClass?: ModelClass): string[]`; use `const resolved = modelClass ?? modelClassOf(model);` then existing expansion. Backward compatible (existing one-arg callers unchanged). With an explicit class, an unknown model still expands (model first + that class's candidates).

2. `src/agent-registry.ts` — add `import type { ModelClass } from "./model-classes.js";`, add `modelClass?: ModelClass;` to `AgentDefinition`, and add explicit `modelClass` to all 9 `DEFAULT_AGENTS`:
   - belayd-scout (mimo-v2.5) → fast
   - belayd-planner (glm-5.3) → frontier
   - belayd-implementer (deepseek-v4-pro) → frontier
   - belayd-reviewer (glm-5.2) → standard
   - belayd-tester (glm-5.2) → standard
   - belayd-userguide (gpt-5.6-luna) → frontier
   - belayd-proof-generator (deepseek-v4-flash) → fast
   - belayd-documenter (gpt-5.6-luna) → frontier
   - belayd-committer (mimo-v2.5) → fast

3. `src/spawn-with-fallback.ts` — add `modelClass?: ModelClass` to `SpawnWithFallbackOptions`; destructure it out (so it does not leak into `SpawnOptions`); resolve via `candidatesForModel(options.model, options.modelClass)`.

4. `extensions/index.ts` — thread `modelClass` through `spawnAgentWithFallback`, `spawnGateRetry`, and `runQualityGate`. In the phase tool execute: `const effectiveModelClass = overrides?.model ? undefined : agent.modelClass;` — when a workflow override changes the model, class follows the OVERRIDDEN model (via `modelClassOf`); otherwise the agent's declared class is used.

5. Tests — `model-classes.test.ts`: explicit-class expansion, backward-compat one-arg call, `DEFAULT_AGENTS.modelClass === modelClassOf(agent.model)` coverage assertion. `spawn-with-fallback.test.ts`: `modelClass` option drives candidate expansion (frontier fallback, not fast).

## Key edge cases

- Unknown model + explicit class → expands (model first + class candidates); unknown + no class → class-of-one (unchanged).
- `agentOverrides.model` set but `agent.modelClass` present → override wins (class from override model).
- `agentOverrides.tools` only → `agent.modelClass` still used (model unchanged).
- `modelClass` must be destructured out of `SpawnWithFallbackOptions` before spreading into `spawnAgentProcess`.

## Note

This task is labeled `research`; the process gate (`research = scout → plan → proof → commit`) has no `implement`/`test` phase. The actual code changes above are planned but NOT implemented here — they require a follow-up `feature` bead.
